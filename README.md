# grill - 产品拷打器

一个 Claude Code skill，从用户视角拷打你的 vibe coding 产品——发现问题、挖掘场景、模拟反馈、帮你完善产品。

## ✨ 功能特性

- 🎯 **智能产品分类** — 自动识别 10 种产品类型，只拷打相关的维度
- 📐 **复杂度自适应** — 根据项目大小自动调整拷打深度（轻量/标准/深度）
- 🔍 **8+2 个场景施压** — 从首次见到多端入口，覆盖用户使用的全流程
- 🔬 **6 个拷打透镜** — 技术风险、商业模式、数据流、合规、增长、运维
- 🧠 **4 种深度拷问** — 5 Whys、反事实推演、极端用户画像、MVP 逆向拆解
- 👥 **5 个证人交叉质询** — 小白用户、目标用户、竞品用户、付费用户、路演观众
- 🏥 **行业视角** — 医学、金融、法律、教育、设计、工程 6 大行业深度场景
- ⚡ **快速拷打模式** — 轻量项目 30 秒出结果
- 📋 **输出分层** — 摘要+详细两层输出，按需展开

## 📋 环境要求

| 要求 | 说明 |
|------|------|
| Claude Code | 需要 Claude Code CLI 或 VS Code 扩展 |
| 联网能力 | WebSearch 工具可用（用于技术栈和竞品调研） |
| 项目路径 | 本地路径或 GitHub 仓库地址 |

**联网功能说明：**

grill 会在分析过程中使用 WebSearch 搜索产品使用的技术栈用途和同类竞品，以提供更精准的产品分类。如果联网不可用，grill 会降级为纯代码分析模式，产品分类准确度会降低但仍然可用。

确保你的 Claude Code 环境可以正常访问网络。如果遇到联网问题：
1. 检查网络连接
2. 确认 Claude Code 版本支持 WebSearch
3. 尝试在终端运行 `curl https://www.google.com` 测试网络

```bash
# 方式 1：克隆到 Claude Code skills 目录
git clone https://github.com/Nokhmily/grill.git ~/.claude/skills/grill

# 方式 2：使用 npx skills（如果支持）
npx skills add Nokhmily/grill
```

## 📖 使用

```bash
# 拷打本地项目
/grill /path/to/your/project

# 拷打 GitHub 仓库
/grill https://github.com/user/repo

# 交互式选择项目
/grill
```

## 📐 拷打流程

```
代码分析 → 复杂度评估 → 产品分类 → 选择拷打角度 → 叠加透镜（可选） → 多维度分析 → 交叉质询 → 去重合并 → 宣判
```

### 核心视角 + 可选透镜

**核心：** 用户视角（默认，必选）
**可选透镜：** 叠加在用户视角之上，增加额外审视角度

| 透镜 | 叠加后增加什么 | 适合什么场景 |
|------|--------------|------------|
| 💰 **投资者透镜** | 变现模式、增长飞轮、技术壁垒 | 想融资、评估商业价值 |
| 🎯 **产品经理透镜** | 差异化定位、数据护城河、竞品对比 | 想做竞品分析、规划路线 |

### 复杂度自适应

| 等级 | 条件 | 深度 | 输出 |
|------|------|------|------|
| 🟢 轻量 | <30 文件 | 3 场景 + 2 证人 | 500 字，30 秒 |
| 🟡 标准 | 30-150 文件 | 6 场景 + 3 证人 | 1500 字 |
| 🔴 深度 | >150 文件 | 全部场景 + 证人 + 透镜 | 完整报告 |

### 产品类型自动识别

通过代码分析 + 联网搜索技术栈用途和同类产品，动态识别产品定位（6 个维度自由组合，不局限于预设类型）。

每种定位自动匹配相关的拷打角度，不相关的自动跳过。

### 拷打透镜（可叠加）

| 透镜 | 核心问题 |
|------|---------|
| 🔬 技术风险 | 代码里埋了多少雷？ |
| 💰 商业拷打 | 这东西怎么赚钱？ |
| 🔄 数据流 | 数据从哪来，到哪去？ |
| ♿ 合规无障碍 | 特殊用户能用吗？合法吗？ |
| 🚀 增长路径 | 用户怎么来，怎么留？ |
| 🖥️ 运维部署 | 上线后能活多久？ |

### 标准拷打（完整流程示例）

以一个待办事项 Web 应用为例，以下是完整的拷打报告：

---

```
🔍 拷打初步报告

产品名称：TodoFlow
一句话定位：一个轻量级的个人待办事项管理工具
目标用户：需要管理日常任务的个人用户

🎯 核心功能：
1. 创建/编辑/删除任务 — 实现在 src/components/TaskList.jsx
2. 任务状态切换（完成/未完成）— 实现在 src/hooks/useTasks.js
3. 按日期筛选任务 — 实现在 src/components/Filter.jsx

🛠️ 技术栈：React + Vite + localStorage

🏆 直接竞品：
- Microsoft To Do — 微软出品，全平台同步
- Todoist — 业界标杆，自然语言输入
- Things 3 — Apple 生态，设计精美

⚠️ 初步可疑点：
- 🔴 任务数据存在 localStorage，刷新不丢但换设备就没了
- 🔴 没有用户系统，无法多设备同步
- 🟡 任务只有标题字段，没有优先级、标签、备注
- 🟡 删除操作没有确认弹窗
- 🟡 没有空状态提示，新用户看到空白页不知道该做什么
```

```
📋 产品定位分析

🎯 核心价值：工具型（任务管理）
👤 目标用户：个人用户
💰 商业模式：免费
🔧 技术架构：纯前端（React + localStorage）
📦 部署方式：静态站点
🌍 开源属性：开源（MIT）

🔍 联网调研结果：
- React 通常用于构建交互式 Web UI
- 市场上有 Todoist、Things 3、Microsoft To Do 等成熟竞品

基于以上定位，以下角度最适合拷打：
- 🔍 问题发现 — 任何产品都适用
- 🎯 场景挖掘 — 找到更多使用场景
- 🔄 数据流 — 数据存储和同步是核心痛点

以下角度暂时不适用：
- 💰 商业拷打 — 免费开源项目，暂无商业化需求
- 🖥️ 运维部署 — 静态站点，部署简单
```

```
🗣️ 证人证词

🌱 证人 1：小白用户 — 小红，25 岁，运营
情境：朋友推荐她用这个管理工作任务
目标：创建并管理每天的工作任务

| 步骤 | 操作 | 看到什么 | 情绪 | 问题 |
|------|------|---------|------|------|
| 1 | 打开网页 | 空白页面 + 右下角 + 按钮 | 困惑 | 不知道 + 是干嘛的，没有引导 |
| 2 | 点击 + | 弹出输入框 | 期待 | 输入任务标题，但没有截止日期选项 |
| 3 | 创建了 3 个任务 | 列表显示 3 个任务 | 一般 | 没有办法设优先级，不知道先做哪个 |
| 4 | 想标记完成 | 点击复选框 | 满意 | 完成了！但完成的任务还是显示在列表里 |
| 5 | 想筛选未完成 | 没找到筛选按钮 | 失望 | 代码里有 Filter 组件但没有入口 |

最终：完成了基本操作，但觉得功能太少，可能回去用 Todoist

🎯 证人 2：目标用户 — 阿杰，30 岁，程序员
情境：想要一个简单的个人任务管理工具
目标：评估这个工具能否替代 Todoist

| 步骤 | 操作 | 看到什么 | 情绪 | 问题 |
|------|------|---------|------|------|
| 1 | 打开网页 | 简洁界面 | 好感 | 第一印象不错，比 Todoist 简洁 |
| 2 | 创建任务 | 输入框 + 提交 | 一般 | 只有标题，没有项目/标签/优先级 |
| 3 | 想导入 Todoist 数据 | 找不到导入功能 | 失望 | 代码里没有 import 相关逻辑 |
| 4 | 想用手机访问 | 浏览器打开 | 失望 | 没有响应式，手机上布局错乱 |

最终：不会迁移，功能差距太大
```

```
⚖️ 判决书

🔴 必须立即修复：
1. 没有空状态提示 — index.html:15 → 新用户看到空白不知道该做什么
   不修的后果：新用户 5 秒内流失
2. 删除没有确认 — TaskList.jsx:42 → 用户误删无法恢复
   不修的后果：一次误删 = 永久流失

🟡 强烈建议修复：
1. 没有响应式设计 — style.css:20 → 手机端无法使用
   不修的后果：移动端用户流失
2. 任务只有标题 — useTasks.js:8 → 无法管理复杂任务
   不修的后果：功能太简单，留不住用户

🟢 建议优化：
1. 添加任务优先级/标签功能
2. 添加数据导出功能（JSON/CSV）
3. 添加截止日期提醒
```

以上是标准模式的完整输出。深度模式会额外包含 6 个拷打透镜分析、行业视角、路演质询等更多维度。

## ❓ 常见问题

### Q: WebSearch 不可用怎么办？
grill 会自动检测联网状态。如果 WebSearch 不可用，会降级为纯代码分析模式——产品分类准确度会降低，但仍然可用。你可以手动告诉 grill 你的产品类型来辅助分析。

### Q: 项目太大（>1000 文件），AI 读不完怎么办？
grill 会自动评估复杂度并调整分析深度。对于超大项目，它会：
- 只读取核心入口文件和关键模块
- 跳过 node_modules、vendor 等依赖目录
- 自动选择"标准"或"深度"模式，而不是全量扫描

### Q: 输出太长了，看不完？
默认输出是"摘要"层（500 字以内），只展示 Top 问题和判决书。想看详细分析时，告诉 grill "展开 [某部分]"即可。

### Q: 非代码项目（设计文件、文档）能用吗？
可以。grill 会自动识别非代码项目并降级为轻量拷打，只分析用户体验、内容质量等维度。

### Q: 和 Claude Code 自带的 code review 有什么区别？
- Claude Code 自带 review：关注**代码质量**（bug、性能、最佳实践）
- grill：关注**用户体验**（用户会遇到什么问题、场景推演、竞品对比）
- 两者互补，不是替代关系

### Q: 可以只拷打某个特定方面吗？
可以。执行 `/grill` 后，从推荐的角度列表中选择你关心的 1-2 个即可。不需要全部分析。

### Q: 同一个项目可以拷打多次吗？
可以。grill 会自动对比上次的拷打结果，标注"已修复 ✅"和"仍存在 ❌"，帮助你追踪改进进度。
