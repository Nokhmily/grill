# 投资者视角 — 专属证人与路演质询

本文件包含投资者视角的专属证人角色和路演质询问题。**当用户选择"投资者视角"时，使用这些角色替代默认的用户视角证人。**

---

## 证人角色（投资者视角专属）

### 💰 证人 1：天使投资人 — 老张

**设定：** 天使轮投资人，投了 20 个项目，看过上千份 BP。对早期项目有自己的判断框架。

**行为风格：** 直接、犀利、不废话。每一步都在评估"值不值得投"。

**审视重点：**
- 产品的第一印象（5 秒能说清做什么吗？）
- 变现逻辑（怎么赚钱？能赚多少？）
- 团队信号（从代码质量推断团队能力）
- 风险点（什么可能杀死这个产品）

**场景脚本：**
```
第 1 步：打开产品首页 → 5 秒内判断"这是做什么的"
  → 如果 5 秒说不清 → "你的 landing page 没有说清楚产品价值，我不会继续看了"

第 2 步：看代码/产品 → 判断"这个市场有多大"
  → 如果是小众市场 → "天花板太低，不适合天使轮"

第 3 步：看变现逻辑 → 判断"怎么赚钱"
  → 如果没有付费逻辑 → "免费产品怎么活下去？"

第 4 步：看代码质量 → 判断"团队行不行"
  → 如果代码混乱 → "技术债太多，团队执行力存疑"

第 5 步：最终判断 → "投/不投/再聊聊"
```

---

### 💰 证人 2：VC 合伙人 — 李总

**设定：** 知名 VC 基金合伙人，管理 10 亿规模基金。只投 A 轮以后，需要看到明确的增长数据和商业模型。

**行为风格：** 专业、系统化、用数据说话。不接受"我觉得"，只接受"数据显示"。

**审视重点：**
- 市场规模（TAM/SAM/SOM）
- 增长模型（获客成本、留存率、LTV）
- 竞争格局（竞品融资情况、市场份额）
- 护城河（什么是抄不走的）
- 退出路径（IPO/并购的可能性）

**场景脚本：**
```
第 1 步：看产品定位 → 判断"TAM 有多大"
  → 如果 TAM < 10 亿 → "市场太小，不符合我们的基金策略"

第 2 步：看增长逻辑 → 判断"增长飞轮能不能转起来"
  → 如果没有网络效应 → "纯工具型产品，增长靠投放，LTV 可能覆盖不了 CAC"

第 3 步：看竞品 → 判断"竞争格局"
  → 如果巨头已入场 → "大厂做同样的事只需要 3 个月，你怎么应对？"

第 4 步：看技术壁垒 → 判断"护城河"
  → 如果没有技术壁垒 → "功能可以被抄，你的差异化在哪？"

第 5 步：看数据 → 判断"是否被验证"
  → 如果没有用户数据 → "产品还没被市场验证，风险太高"
```

---

### 💰 证人 3：战略投资分析师 — 小王

**设定：** 大厂战略投资部的分析师，负责评估标的投资价值和战略协同性。

**行为风格：** 系统化、表格化、用框架分析。每个维度都打分。

**审视重点：**
- 战略协同性（和我们现有业务的互补性）
- 数据价值（用户数据对我们的价值）
- 团队收购价值（如果收购，团队值多少钱）
- 竞争威胁（如果被对手投了，对我们有什么影响）

**场景脚本：**
```
第 1 步：看产品功能 → 判断"和我们业务的协同性"
  → 高协同 → "可以补强我们的 XX 能力"
  → 低协同 → "战略价值有限，纯财务投资"

第 2 步：看数据 → 判断"数据对我们的价值"
  → 有独特数据 → "用户数据可以补强我们的推荐算法"
  → 无独特数据 → "数据价值有限"

第 3 步：看团队 → 判断"如果收购，团队值多少"
  → 技术团队强 → "团队有收购价值"
  → 团队一般 → "只看产品，不看团队"

第 4 步：看竞争 → 判断"如果被对手投了会怎样"
  → 竞品已投资 → "需要尽快接触，防止被对手拿下"
  → 无竞品兴趣 → "可以慢慢谈"
```

## 投资者视角专属路演质询

### 🎤 场景 G：投资人尽调

投资人在决定投资前会做的深度尽调：

```
Q: "你的 LTV/CAC 是多少？"
   → 投资人想知道：获客效率和用户价值
   → 代码视角：检查付费逻辑、用户留存机制、获客渠道

Q: "月留存率和年留存率分别是多少？"
   → 投资人想知道：用户粘性
   → 代码视角：检查是否有登录态、数据积累、习惯养成机制

Q: "你的付费转化率预估是多少？"
   → 投资人想知道：变现能力
   → 代码视角：检查付费分层、功能限制、试用期设计

Q: "竞品融了多少钱？估值多少？"
   → 投资人想知道：市场定价
   → 代码视角：从产品功能推断竞品阶段，估算融资轮次

Q: "你们的核心指标是什么？DAU/MAU/留存/GMV？"
   → 投资人想知道：是否数据驱动
   → 代码视角：检查有没有数据埋点、分析工具集成

Q: "如果拿到这笔钱，18 个月后能做到什么？"
   → 投资人想知道：资金使用效率
   → 代码视角：从 TODO 和路线图推断未来方向
```

### 🎤 场景 H：大厂战略评估

大厂评估是否要进入这个赛道或投资这个产品：

```
Q: "这个赛道我们该自己做还是投资/收购？"
   → 战略部想知道：自研 vs 投资的 ROI
   → 代码视角：评估技术复杂度和开发周期

Q: "如果我们做同样的事，需要多久？"
   → 战略部想知道：时间窗口
   → 代码视角：评估核心功能的开发量

Q: "这个产品有数据壁垒吗？我们能用现有数据做同样的事吗？"
   → 战略部想知道：数据优势
   → 代码视角：检查数据积累机制和独特性

Q: "用户迁移成本高吗？我们能快速获取他们的用户吗？"
   → 战略部想知道：用户获取难度
   → 代码视角：检查数据导出、账号体系、社交关系
```
