# 拷打透镜 — 6 个额外拷打角度

除了用户选择的分析模式外，还可以叠加以下透镜进行更深度的拷打。**每个透镜都是一个问题过滤器——用它重新审视产品，会看到不同的问题。**

---

## 🔬 透镜 1：技术风险拷打 — "代码里埋了多少雷？"

不看功能，只看风险。从代码中找出所有可能爆炸的点：

| 拷打方向 | 从代码中找什么 | 会发现什么 |
|---------|--------------|-----------|
| 🔒 安全漏洞 | 用户输入是否清洗、API 是否有鉴权、敏感信息是否暴露 | XSS、SQL 注入、密钥泄露 |
| 💣 架构隐患 | 单点故障、硬编码配置、耦合度 | 一个模块挂了整个产品就挂了 |
| 📦 依赖风险 | 第三方库的维护状态、版本、已知漏洞 | 用了废弃的库、有 CVE 未修复 |
| 🧪 测试覆盖 | 有没有测试、测试覆盖了什么 | 核心逻辑零测试，改一行可能炸一片 |
| 📝 代码质量 | TODO/FIXME/HACK 注释、重复代码、过长函数 | 技术债堆积，越改越难改 |

---

## 💰 透镜 2：商业拷打 — "这东西怎么赚钱？"

不看功能，只看商业逻辑。产品能活下来吗？

| 拷打方向 | 从代码中找什么 | 会发现什么 |
|---------|--------------|-----------|
| 💵 变现模式 | 付费分层、支付集成、订阅逻辑 | 没有付费入口 = 纯烧钱 |
| 📊 单位经济 | 用户获取成本 vs 用户终身价值 | 获客成本比收入还高 |
| 🏰 护城河 | 独特算法、数据积累、网络效应 | 和竞品同质化，没有壁垒 |
| 🔄 留存机制 | 通知、提醒、习惯养成、数据沉淀 | 用完一次就走了，没有理由回来 |
| 📈 增长引擎 | 分享、邀请、口碑传播机制 | 没有病毒传播路径，全靠买量 |

---

## 🔄 透镜 3：数据流拷打 — "数据从哪来，到哪去，谁能看？"

追踪数据的完整生命周期：输入 → 存储 → 处理 → 展示 → 传输 → 删除

每个环节都要问：
- 数据从哪里来？（用户输入？第三方 API？爬虫？）
- 存在哪里？（本地？云端？数据库？）
- 谁能看到？（本人？管理员？第三方？）
- 保留多久？（永久？有清理机制吗？）
- 能删除吗？（用户能要求删除自己的数据吗？）

---

## ♿ 透镜 4：合规与无障碍拷打 — "特殊用户能用吗？合法吗？"

| 拷打方向 | 检查点 | 为什么重要 |
|---------|--------|-----------|
| ♿ 无障碍 | 键盘导航、屏幕阅读器支持、颜色对比度、alt 文本 | 全球 15% 人口有残障 |
| 🌍 国际化 | 多语言支持、RTL 布局、时区处理、货币格式 | 想出海就必须做 |
| 🔒 GDPR | 数据同意、删除权、数据导出、隐私政策 | 欧洲用户的法律要求 |
| 📱 隐私 | 权限请求合理性、数据最小化原则 | Apple/Google 隐私审核越来越严 |
| 📋 行业合规 | 医疗 HIPAA、支付 PCI DSS、教育 FERPA | 特定行业的准入门槛 |

---

## 🚀 透镜 5：增长拷打 — "用户怎么来，怎么留，怎么传？"

追踪 AARRR 海盗指标：获客 → 激活 → 留存 → 推荐 → 收入

每个阶段都要问：
- 获客：用户从哪里知道这个产品？入口在哪？
- 激活：新用户第一次使用时的体验如何？能快速感受到价值吗？
- 留存：用户第二天/第七天/第三十天还会回来吗？
- 推荐：用户会主动推荐给别人吗？有传播机制吗？
- 收入：用户愿意付费吗？付费转化率如何？

---

## 🖥️ 透镜 6：运维拷打 — "上线后能活多久？"

| 拷打方向 | 检查点 | 会发现什么 |
|---------|--------|-----------|
| 🚀 部署 | 有没有 CI/CD、部署脚本、环境配置 | 还在手动部署 |
| 📊 监控 | 有没有日志、错误追踪、性能监控 | 出了问题不知道 |
| 💾 备份 | 数据有没有备份机制、恢复流程 | 数据丢了就真丢了 |
| 📈 扩容 | 能不能水平扩展、有没有瓶颈 | 100 用户没问题，10000 用户就挂 |
| 🔒 SSL/域名 | 有没有 HTTPS、域名配置 | 用 IP 地址访问，浏览器会警告不安全 |
