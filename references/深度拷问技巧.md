# 深度拷问技巧 — 4 种追加拷打手段

当常规分析还不够深入时，使用以下技巧进行更深层的拷打。

**什么时候用哪个技巧：**

| 技巧 | 触发条件 | 什么时候用 |
|------|---------|-----------|
| 🥊 5 Whys | 发现了问题但不确定根本原因 | "用户流失率高" → 追问为什么 → 找到根因是缺少引导 |
| 🔄 反事实推演 | 想验证某个设计决策是否合理 | "为什么用 localStorage 而不是云端？" → 反事实推演验证 |
| 🎯 极端用户画像 | 想知道专业用户会怎么评价 | 产品面向专业群体时，用最挑剔的视角审视 |
| 🏗️ MVP 逆向拆分 | 想区分核心功能和非核心功能 | 产品功能很多但不确定哪些是 MVP 必须的 |

**不要滥用：** 每个技巧最多用 2-3 次，找到答案就停。5 Whys 追到第 3 层还没找到根因，说明问题可能不在代码层面。

---

## 🥊 技巧 1：5 Whys 追问法 — "连续问 5 个为什么"

对每一个发现的问题，连续追问 5 次"为什么"，直到找到根本原因：

```
问题：用户注册后流失率很高
→ Why 1：为什么流失？→ 因为注册后看到空页面，不知道该做什么
→ Why 2：为什么不知道做什么？→ 因为没有引导流程
→ Why 3：为什么没有引导？→ 因为开发者觉得自己会用，觉得用户也会用
→ Why 4：为什么这样假设？→ 因为没有做过用户测试
→ Why 5：为什么没做？→ 因为这是一个人的 side project，没有用户反馈渠道
→ 根本原因：缺少用户反馈机制，导致所有假设都无法验证
```

从代码中找什么：
- 找到问题的直接原因（代码层面）
- 追问为什么代码是这样写的（设计决策层面）
- 追问为什么这个决策没被质疑（流程层面）

---

## 🔄 技巧 2：反事实推演 — "如果反过来做呢？"

对产品的每个核心决策，假设它做了相反的选择，看会发生什么：

```
当前决策：表单数据存在 localStorage
反事实：如果存在云端呢？
→ 用户换设备不会丢数据
→ 但需要账号系统，增加注册门槛
→ 需要服务器成本
→ 但用户留存会提高（数据在就不容易走）
→ 结论：localStorage 是 MVP 的合理选择，但长期必须迁移到云端
```

```
当前决策：免费产品，没有付费功能
反事实：如果收费 $5/月呢？
→ 会流失 90% 的用户
→ 但剩下的 10% 可能是真正需要的用户
→ 有收入才能持续开发
→ 但需要先证明价值才能收费
→ 结论：应该先做 Freemium，免费版证明价值，付费版解锁高级功能
```

## 🎯 技巧 3：极端用户画像 — "最挑剔的用户会怎么说？"

想象一个极端挑剔的用户，他会怎么评价这个产品：

```
极端用户画像：
- 用了 10 年竞品的专业用户
- 对每一个细节都有高要求
- 不会给你第二次机会

他会说什么：
- "[竞品] 3 秒就能完成的事情，你这里要点 5 步"
- "这个快捷键和 [竞品] 不一样，我要重新学？"
- "你的导出格式不支持 [格式]，我没法用"
- "界面太花了，我只想快速完成任务"
```

从代码中找什么：
- 与竞品的核心交互差异
- 缺失的快捷操作
- 缺少的专业功能
- 界面复杂度

---

## 🏗️ 技巧 4：MVP 逆向拆解 — "这个产品的 MVP 应该是什么？"

反过来想：如果从零开始做这个产品，**最小可行版本**应该包含什么？当前产品做了哪些"超前"的功能，又漏了哪些"基础"的功能？

```
MVP 应该有的（核心价值闭环）：
✅ [功能 A] — 这是产品的核心价值
✅ [功能 B] — 没有它用户无法完成核心任务
✅ [功能 C] — 没有它产品不可用

当前产品做了但可以推后的：
🟡 [功能 D] — 锦上添花，但 MVP 阶段不需要
🟡 [功能 E] — 有总比没有好，但不是核心

当前产品漏了但 MVP 必须有的：
🔴 [功能 F] — 没有它用户无法上手
🔴 [功能 G] — 没有它用户会立刻流失
```

从代码中找什么：
- 核心功能的代码完整度
- 非核心功能的代码占比
- 缺失的基础功能
