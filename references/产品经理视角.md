# 产品经理视角 — 完整分析框架

本文件包含产品经理视角的完整分析内容。**当用户选择"产品经理视角"时，读取此文件。**

---

## 产品经理视角的核心问题

产品经理不关心"代码质量"，他们关心：
1. **这个产品在市场中占什么位置？** — 竞品、差异化、生态位
2. **用户为什么选它而不选竞品？** — 核心价值、迁移成本、口碑
3. **增长飞轮怎么转？** — 用户→数据→产品→更多用户
4. **数据能形成壁垒吗？** — 用户数据、行为数据、内容数据
5. **下一步该做什么？** — 产品路线图、优先级、资源分配

---

## 分析维度 1：差异化定位拷打

从代码中找出产品和竞品的核心区别：

| 对比维度 | 分析方法 | 会发现什么 |
|---------|---------|-----------|
| 功能组合 | 有哪些功能是竞品没有的？ | 差异化卖点 |
| 交互方式 | 操作路径和竞品有什么不同？ | 体验差异化 |
| 技术实现 | 用了什么不同的技术方案？ | 技术差异化 |
| 目标用户 | 面向的是竞品忽略的群体？ | 市场差异化 |
| 定价策略 | 定价和竞品有什么不同？ | 商业差异化 |

**拷打问题：**
- "和竞品相比，你的核心差异是什么？一句话能说清吗？"
- "如果竞品抄了你的核心功能，你还剩什么？"
- "用户为什么不用竞品而来用你？这个理由够强吗？"

## 分析维度 2：增长飞轮拷打

分析产品是否具有"飞轮效应"：

```
增长飞轮类型：

1. 数据飞轮：用户越多 → 数据越多 → 产品越好 → 更多用户
   示例：推荐算法、搜索引擎

2. 网络飞轮：用户越多 → 其他用户价值越大 → 更多用户
   示例：社交网络、协作工具

3. 内容飞轮：用户越多 → 内容越多 → 吸引更多用户
   示例：UGC 平台、社区

4. 品牌飞轮：用户越多 → 口碑越好 → 获客成本越低
   示例：Slack、Notion
```

从代码中找什么：
- 有没有 UGC 机制
- 有没有分享/邀请功能
- 数据是否随使用量增长而增值
- 有没有用户间互动

**拷打问题：**
- "用户越多，产品会越好用吗？哪种飞轮？"
- "用户有没有动力主动分享？"
- "10 个用户和 10000 个用户的体验有区别吗？"

---

## 分析维度 3：数据护城河拷打

评估用户数据能否形成竞争壁垒：

| 数据类型 | 壁垒强度 | 示例 |
|---------|---------|------|
| 用户行为数据 | 🟡 中等 | 搜索历史、浏览偏好 |
| 用户内容数据 | 🟢 较强 | 笔记、文档、设计稿 |
| 社交关系数据 | 🔴 很强 | 通讯录、关注关系 |
| 专有训练数据 | 🔴 很强 | AI 模型的训练数据 |
| 用户习惯数据 | 🟡 中等 | 快捷键、自定义配置 |

从代码中找什么：
- 数据存储方式（本地 vs 云端）
- 数据是否可导出
- 是否有数据积累机制
- 是否有推荐/个性化逻辑

**拷打问题：**
- "用户的数据能导出吗？如果能，迁移成本高吗？"
- "用户用得越久，产品会越好用吗？"
- "你的数据和竞品的数据有什么不同？"

## 分析维度 4：产品路线图拷打

从代码中推断产品的下一步方向：

| 线索 | 从代码中找什么 | 会发现什么 |
|------|--------------|-----------|
| TODO/FIXME | 代码中的待办注释 | 开发者计划做什么 |
| 半成品功能 | 有代码但没有入口的功能 | 正在开发但没完成 |
| 依赖升级 | package.json 中的版本号 | 技术债务和升级计划 |
| 配置项 | 环境变量、配置文件 | 预留的扩展能力 |
| 文档 | README、CHANGELOG | 产品路线图信息 |

**拷打问题：**
- "代码里有哪些半成品功能？什么时候能上线？"
- "TODO 列表里有什么？优先级是什么？"
- "从依赖升级看，技术债务多不多？"

---

## 分析维度 5：架构决策拷打

评估技术选型对产品的影响：

| 架构决策 | 影响 | 评估标准 |
|---------|------|---------|
| 前端框架 | 开发效率、性能、生态 | 是否适合产品类型 |
| 数据库 | 扩展性、成本、一致性 | 是否能支撑数据量增长 |
| API 设计 | 可扩展性、集成能力 | 是否便于未来扩展 |
| 部署方式 | 成本、可靠性、扩展性 | 是否能支撑用户增长 |

**拷打问题：**
- "技术选型是否适合产品当前阶段？"
- "如果用户量增长 10 倍，架构能支撑吗？"
- "有没有明显的技术债务需要偿还？"

---

## 分析维度 6：生态位拷打

评估产品在市场中的位置：

```
生态位分析矩阵：

                高
        功能    │  专业工具区
        完整度  │  （Notion、Figma）
                │
                │     ← 你的产品在这里？
                │
        低      │  轻量工具区
                │  （Todoist、Carrd）
                └──────────────────
                   低    目标用户量    高
```

从代码中推断：
- 功能复杂度 → 功能完整度轴
- 目标用户 → 用户量轴
- 定价策略 → 市场定位

**拷打问题：**
- "你的产品在市场中处于什么位置？轻量还是专业？"
- "你的目标用户和竞品的用户重叠度高吗？"
- "你的产品是在存量市场竞争还是增量市场？"

## 产品经理视角的输出格式

```
🎯 产品经理视角分析报告

📊 差异化定位
├─ 核心差异：[一句话说清]
├─ 差异化类型：[功能/体验/技术/市场/商业]
├─ 差异化强度：[强/中/弱]
└─ 可持续性：[能维持多久]

📈 增长飞轮
├─ 飞轮类型：[数据/网络/内容/品牌]
├─ 飞轮转速：[快/中/慢/还没转起来]
├─ 关键节点：[飞轮中最薄弱的环节]
└─ 加速建议：[怎么让飞轮转得更快]

🔒 数据护城河
├─ 数据类型：[用户行为/内容/社交/专有]
├─ 壁垒强度：[强/中/弱]
├─ 可迁移性：[用户能轻松带走数据吗]
└─ 增值潜力：[数据越多产品越好吗]

🗺️ 产品路线图
├─ 当前阶段：[MVP/增长/成熟]
├─ 下一步方向：[从代码推断]
├─ 技术债务：[多/中/少]
└─ 优先级建议：[先做什么]

🏗️ 架构评估
├─ 技术选型：[是否适合]
├─ 扩展性：[能支撑多大增长]
├─ 技术债务：[需要还多少]
└─ 建议：[架构层面的改进方向]

🌍 生态位
├─ 市场位置：[轻量/中端/专业]
├─ 目标用户：[和竞品重叠度]
├─ 市场类型：[增量/存量]
└─ 竞争策略：[差异化/成本/聚焦]

📋 产品建议
├─ 产品层面：[最重要的 3 个改进]
├─ 增长层面：[最重要的 3 个行动]
└─ 战略层面：[最需要思考的 3 个问题]
```
