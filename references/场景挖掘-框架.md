# 场景挖掘框架

本文件包含场景挖掘模式的完整框架和示例。**主文件 `skill.md` 只引用本文件。**

---

## 核心方法：从代码能力出发，推导真实场景

不是问"这个产品能做什么"，而是问"一个真实的人在什么情况下会打开这个产品，用它来做什么，做完之后呢？"

**执行步骤：**

1. 从代码中提取产品的**核心能力清单**（不是功能列表，是"这个产品能帮用户做到什么"）
2. 对每个能力，问三个问题：
   - 谁会需要这个能力？在什么情境下？
   - 这个能力能独立使用，还是必须配合其他功能？
   - 使用这个能力后，用户的下一步行动是什么？

## 4 个场景深度推演

### 场景 A：核心场景 — 产品设计的本来用途

不是简单描述"用户可以用它做 XX"，而是写出一个完整的**用户故事**：

```
故事格式：
[用户角色] 在 [什么情境下] 想要 [完成什么目标]，
于是打开了这个产品。
他们需要经过 [具体步骤]，
最终 [达成结果 / 遇到阻碍]。
```

从代码中找什么：
- 入口页面 → 用户的第一印象
- 核心交互流程 → 用户的操作路径
- 数据存储方式 → 用户的使用频率和数据积累方式

示例（以一个 Markdown 编辑器为例）：
```
一个技术博主在写一篇 5000 字的教程文章，
需要实时预览 Markdown 渲染效果。
他打开了这个编辑器，左边写 Markdown，右边看预览。
写到第 3000 字时，右边预览区开始出现明显卡顿，
每次输入一个字符都要等 0.5 秒才能看到渲染结果。
他发现代码里用 `marked.parse()` 做实时渲染，没有做防抖——
每输入一个字符就重新解析整篇文章。
```

---

### 场景 B：延伸场景 — 换个用户、换个用法

从代码中找到产品的**隐含能力**，推导非预期但合理的使用方式：

推演方法：
- 代码中有 A 功能和 B 功能，如果只用 A 不用 B，能做什么？
- 如果用户群体从 [目标用户] 变成 [另一个群体]，他们会怎么用？
- 如果数据从 [预期类型] 变成 [非预期类型]，会怎样？

示例（以一个 Markdown 编辑器为例）：
- 代码支持代码高亮 → 可以当作代码片段管理器（但没有标签和搜索功能）
- 代码支持导出 HTML → 可以当作简单的邮件模板生成器（但没有 HTML 编辑能力）
- 代码支持实时预览 → 可以当作教学演示工具（但没有分屏分享功能）

---

### 场景 C：压力场景 — 数据量、并发量、极端输入

从代码的具体实现推导性能瓶颈：

从代码中找什么：
- 数据加载方式（全量 vs 分页）→ 推导数据量增长后的表现
- 渲染方式（全部渲染 vs 虚拟列表）→ 推导大量数据时的性能
- 计算方式（实时计算 vs 缓存）→ 推导高并发时的表现

示例（以一个 Markdown 编辑器为例）：
- 代码用 `marked.parse(fullText)` 每次解析全文 → 单篇超过 1 万字时渲染延迟明显
- 代码把所有笔记存在内存里（`const notes = []`）→ 关闭浏览器后数据丢失（如果没用 IndexedDB）
- 代码没有做并发控制 → 如果同时打开多个标签页编辑同一篇笔记，数据会互相覆盖

---

### 场景 D：协作场景 — 分享、多人使用

如果产品涉及数据分享或多人使用，推演协作场景：

- 用户想把结果分享给别人，能做到吗？
- 多人同时使用时会发生什么？
- 数据在不同设备间能同步吗？

从代码中找什么：
- 分享功能的代码（导出、分享链接、权限设置）
- 数据同步逻辑（如果有）
- 多用户并发处理（如果有）

示例（以一个 Markdown 编辑器为例）：
- 代码没有分享功能，用户想把写好的文章发给同事只能导出文件再发微信
- 代码没有云端同步，换一台电脑就找不到之前写的内容了
- 如果两个同事同时编辑同一篇文章（各自本地副本），合并时会冲突

## 输出格式

```
🎯 场景深度推演

📌 核心场景（用户故事）
[完整的用户故事，包含：谁、什么情境、什么目标、操作路径、遇到的问题]

🔄 延伸场景（隐含能力）
1. [场景] — 代码支撑点：[哪个功能]，当前缺口：[需要补充什么]

⚡ 压力场景（性能瓶颈）
1. [场景] — 代码瓶颈：[哪段代码]，触发条件：[什么情况下]，表现：[会怎样]

🤝 协作场景（多人/多设备）
1. [场景] — 当前支持：[能/不能]，代码现状：[具体实现]，建议：[怎么改]
```
