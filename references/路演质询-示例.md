# 路演质询示例库

以下是 6 类路演场景的完整问题清单。**实际执行时，根据产品的类型选择最相关的 2-3 类场景，不需要全部执行。**

选择建议：
- 个人项目 / 开源项目 → 场景 A（Demo Day）+ 场景 C（技术分享）
- SaaS 产品 → 场景 A + 场景 B（投资人）+ 场景 D（合作洽谈）
- 有商业化意图 → 场景 B（投资人）+ 场景 D（合作洽谈）
- 开源项目 → 场景 C（技术分享）+ 场景 F（开源社区）

---

## 🎤 场景 A：Demo Day / 黑客松答辩

评委在看你的 3 分钟演示，结束后会追问：

```
Q: "你的产品和 [竞品 X] 的核心区别是什么？"
   → 评委想知道：你做了竞品分析吗？你的差异化在哪？
   → 代码视角：从功能清单中找出竞品没有的能力，或者用不同方式解决同一个问题

Q: "这个技术方案是你自己想的还是套用的模板？"
   → 评委想知道：你对技术选型有没有自己的思考
   → 代码视角：检查技术栈选择是否合理，有没有明显的大材小用或小材大用

Q: "你觉得这个产品最大的风险是什么？"
   → 评委想知道：你有没有风险意识，能不能坦诚面对不足
   → 代码视角：直接指出代码中最大的技术债或功能缺口

Q: "如果给你一个月，你最想加什么功能？"
   → 评委想知道：你的产品规划能力和优先级判断
   → 代码视角：从代码中的半成品和缺失功能中推断最该补的

Q: "这个项目几个人做的？做了多久？"
   → 评委想知道：效率和团队协作能力
   → 代码视角：从 commit 历史和代码量推断工作量
```

## 🎤 场景 B：投资人路演

VC 在评估是否值得投，关注市场和商业：

```
Q: "这个市场的天花板有多高？"
   → 投资人想知道：市场空间是否足够大
   → 代码视角：从产品功能定位推断目标市场，评估是垂直小众还是大众需求

Q: "你的变现模式是什么？"
   → 投资人想知道：怎么赚钱
   → 代码视角：检查代码中有没有付费分层、API 限额、高级功能入口

Q: "如果大厂做同样的事情，你怎么应对？"
   → 投资人想知道：护城河在哪
   → 代码视角：从技术实现中找差异化——是算法独特、数据积累、还是垂直场景的深度理解

Q: "你的获客成本预估是多少？"
   → 投资人想知道：增长可行性
   → 代码视角：从产品形态推断获客方式（病毒传播？内容营销？销售驱动？）

Q: "现在的数据表现怎么样？DAU、留存率、转化率？"
   → 投资人想知道：产品是否被验证
   → 代码视角：检查有没有数据埋点和分析集成——如果没有，说明还没到数据驱动阶段
```

## 🎤 场景 C：技术分享 / 开发者社区

技术同行在评估你的技术能力：

```
Q: "为什么选这个框架而不是 [另一个]？"
   → 同行想知道：技术选型的思考过程
   → 代码视角：从 package.json 的依赖中分析选型合理性

Q: "这个架构能支撑多大的用户量？"
   → 同行想知道：技术的可扩展性
   → 代码视角：检查架构是单体还是微服务，有没有缓存层，数据库设计是否考虑扩展

Q: "代码里有什么技术债是你知道但还没还的？"
   → 同行想知道：你的技术自省能力
   → 代码视角：直接指出代码中的 TODO、hack、硬编码、重复代码

Q: "有没有写测试？覆盖率多少？"
   → 同行想知道：工程质量意识
   → 代码视角：检查有没有 test 文件，测试框架是什么

Q: "这个项目的 CI/CD 是怎么做的？"
   → 同行想知道：工程化水平
   → 代码视角：检查有没有 GitHub Actions、Dockerfile、部署脚本
```

## 🎤 场景 D：合作洽谈

潜在合作方在评估是否值得对接：

```
Q: "你们有没有 API？我能对接吗？"
   → 合作方想知道：技术对接的可行性
   → 代码视角：检查有没有 REST/GraphQL API，有没有 API 文档，有没有开放接口

Q: "数据安全怎么保障？"
   → 合作方想知道：数据合规性
   → 代码视角：检查数据加密、认证机制、隐私政策

Q: "如果我们要定制开发，你们能支持吗？"
   → 合作方想知道：灵活度
   → 代码视角：检查代码的模块化程度、配置化程度、是否容易扩展

Q: "你们的数据格式是什么？能导入我们的数据吗？"
   → 合作方想知道：数据兼容性
   → 代码视角：检查数据模型，是否支持标准格式导入导出
```

## 🎤 场景 E：媒体采访 / 公众号文章

记者在写报道，关注故事和价值：

```
Q: "这个产品的灵感从哪来？"
   → 记者想知道：创始人故事
   → 代码视角：从代码注释、README、commit message 中提取项目起源故事

Q: "你觉得这个产品最大的创新点是什么？"
   → 记者想知道：技术或产品亮点
   → 代码视角：从功能组合和交互设计中找到"别人没做过"的点

Q: "现在用户反馈怎么样？"
   → 记者想知道：市场验证
   → 代码视角：检查有没有用户反馈入口、评价系统、社区讨论

Q: "未来有什么计划？"
   → 记者想知道：产品愿景
   → 代码视角：从 TODO、Roadmap 文件、半成品功能中推断下一步方向
```

## 🎤 场景 F：开源社区贡献者

如果产品是开源的（或有开源组件），社区贡献者会审视代码质量和贡献体验：

```
Q: "贡献指南在哪？我怎么提 PR？"
   → 贡献者想知道：参与门槛高不高
   → 代码视角：检查有没有 CONTRIBUTING.md、Issue 模板、PR 模板

Q: "代码风格统一吗？有没有 lint 配置？"
   → 贡献者想知道：代码规范是否清晰
   → 代码视角：检查 .eslintrc、.prettierrc、stylelint 等配置文件

Q: "本地开发环境搭建要多久？"
   → 贡献者想知道：上手成本
   → 代码视角：检查 README 里的开发指南、docker-compose 配置、环境变量数量

Q: "测试好跑吗？覆盖率多少？"
   → 贡献者想知道：改代码会不会不小心搞坏东西
   → 代码视角：检查测试配置、CI 里有没有自动跑测试

Q: "Issue 响应速度怎么样？维护者活跃吗？"
   → 贡献者想知道：社区是否健康
   → 代码视角：检查最近的 commit 频率、Issue/PR 的响应时间、有没有 stale bot

Q: "License 是什么？我能商用吗？"
   → 贡献者想知道：法律风险
   → 代码视角：检查 LICENSE 文件，是 MIT/Apache 还是 GPL/AGPL

Q: "项目依赖安全吗？有没有已知漏洞？"
   → 贡献者想知道：供应链风险
   → 代码视角：检查有没有 Dependabot/Snyk 配置、npm audit 是否通过
```
