# 投资者视角 — 完整分析框架

本文件包含投资者视角的完整分析内容。**当用户选择"投资者视角"时，读取此文件。**

---

## 投资者视角的核心问题

投资者不关心"产品好不好用"，他们关心：
1. **这个产品能赚多少钱？** — 市场规模、变现模式、单位经济
2. **这个产品能不能持续增长？** — 增长飞轮、网络效应、病毒传播
3. **这个产品有没有护城河？** — 技术壁垒、数据壁垒、品牌壁垒
4. **这个团队能不能做成？** — 团队背景、执行力、融资情况
5. **风险是什么？** — 竞争风险、监管风险、技术风险

---

## 分析维度 1：变现模式拷打

从代码中找出所有与"钱"相关的逻辑：

| 检查点 | 从代码中找什么 | 会发现什么 |
|--------|--------------|-----------|
| 付费分层 | 有没有 free/pro/enterprise 的功能区分 | 没有分层 = 没有变现路径 |
| 支付集成 | Stripe/支付宝/微信支付的代码 | 有支付 = 已经在变现 |
| API 限额 | API 调用次数限制、速率限制 | 限额 = 潜在的付费点 |
| 高级功能 | 代码里有但没有开放的功能 | 可能是未来的付费功能 |
| 广告集成 | 广告 SDK、广告位 | 广告模式 = 靠流量赚钱 |

**拷打问题：**
- "代码里有支付逻辑吗？如果有，定价是多少？如果没有，打算怎么赚钱？"
- "免费版和付费版的功能区分是什么？这个区分合理吗？"
- "用户的付费意愿如何？从功能完整度看，用户愿意为这个付多少钱？"

---

## 分析维度 2：增长飞轮拷打

分析产品的增长是否具有"飞轮效应"——用户越多→产品越好→吸引更多用户：

```
增长飞轮模型：

用户增长 → 数据积累 → 产品变好 → 用户留存 → 口碑传播 → 更多用户
    ↑                                                    ↓
    └────────────────────────────────────────────────────┘
```

从代码中找什么：
- 有没有用户生成内容（UGC）的机制
- 有没有分享/邀请功能
- 数据是否随使用量增长而增值
- 有没有网络效应（用户间互动）

**拷打问题：**
- "用户越多，产品会越好用吗？还是只是数据堆积？"
- "用户有没有动力主动分享这个产品？"
- "如果 10 个用户和 10000 个用户用这个产品，体验有区别吗？"

## 分析维度 3：技术壁垒拷打

评估产品的技术壁垒——什么能被抄走，什么抄不走：

| 壁垒类型 | 能否被抄 | 示例 |
|---------|---------|------|
| 功能实现 | ❌ 容易抄 | 表单构建、任务管理、笔记功能 |
| 交互设计 | 🟡 部分可抄 | 独特的操作方式、创新的 UI 模式 |
| 算法/模型 | 🟡 需要时间 | 推荐算法、AI 模型、搜索引擎 |
| 数据积累 | ❌ 抄不走 | 用户行为数据、内容库、关系图谱 |
| 生态/集成 | ❌ 抄不走 | 插件生态、API 生态、用户习惯 |

**拷打问题：**
- "如果大厂明天做一模一样的产品，你的用户会走吗？"
- "你的核心壁垒是技术、数据还是品牌？"
- "这个壁垒需要多长时间才能建立？"

## 分析维度 4：团队背景拷打

从代码和项目信息推断团队情况：

| 检查点 | 从代码中找什么 | 会发现什么 |
|--------|--------------|-----------|
| 代码质量 | 命名规范、注释、测试 | 团队的工程能力 |
| 迭代速度 | commit 频率、功能更新节奏 | 团队的执行力 |
| 技术选型 | 框架选择、架构设计 | 团队的技术判断力 |
| 文档质量 | README、API 文档 | 团队的产品意识 |
| 开源活跃度 | Issue 响应、PR 合并速度 | 团队的社区运营能力 |

**拷打问题：**
- "从代码质量看，这个团队的工程能力如何？"
- "从迭代速度看，这个团队的执行力如何？"
- "这个团队之前做过什么产品？成功率如何？"

## 分析维度 5：单位经济拷打

估算产品的单位经济模型：

```
单位经济公式：
LTV（用户终身价值）= ARPU（每用户平均收入）× 用户生命周期
CAC（获客成本）= 营销总支出 / 新增用户数
盈亏平衡点 = CAC / ARPU（月）
```

从代码中推断：
- ARPU：从定价和功能分层推断
- 用户生命周期：从留存机制和数据沉淀推断
- CAC：从获客渠道推断（SEO = 低，付费广告 = 高）

**拷打问题：**
- "这个产品的 ARPU 大概是多少？"
- "用户平均会用多久？"
- "获客成本大概是多少？"

---

## 分析维度 6：战略威胁拷打

评估产品对大厂的战略威胁：

| 威胁等级 | 条件 | 大厂的反应 |
|---------|------|-----------|
| 🔴 高威胁 | 抢占核心用户、有网络效应、增长快 | 立即立项对标 |
| 🟡 中威胁 | 在垂直领域有优势、可能蚕食边缘用户 | 观察 + 拦截 |
| 🟢 低威胁 | 用户群不重叠、市场太小、增长慢 | 忽略 |

**拷打问题：**
- "如果这个产品增长 10 倍，会威胁到谁？"
- "大厂做同样的事，需要多久？成本多高？"
- "这个产品的市场是增量还是存量？"
