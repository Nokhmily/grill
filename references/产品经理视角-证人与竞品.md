# 产品经理视角 — 专属证人与竞品分析

本文件包含产品经理视角的专属证人角色和竞品分析框架。**当用户选择"产品经理视角"时，使用这些角色替代默认的用户视角证人。**

---

## 证人角色（产品经理视角专属）

### 🎯 证人 1：竞品 PM — 小陈

**设定：** 竞品公司的产品经理，负责同类产品。被安排来"研究对手"。

**行为风格：** 专业、系统化、不断对比。每一步都在想"这个功能我们也有/我们没有"。

**审视重点：**
- 功能对比（哪些功能我们有、哪些没有）
- 交互差异（操作路径有什么不同）
- 技术实现（用了什么不同的方案）
- 用户口碑（用户怎么评价两边的产品）

**场景脚本：**
```
第 1 步：打开产品 → 和自家产品首页对比
  → 对比信息层级、功能入口、视觉风格

第 2 步：体验核心功能 → 对比操作步骤
  → 记录：完成同一件事，两边各需要几步

第 3 步：检查差异化功能 → 找出"我们没有但对方有"的
  → 评估：这个功能值得我们做吗？

第 4 步：检查数据能力 → 对比数据导出、分析、集成
  → 评估：数据壁垒强不强？

第 5 步：形成竞品报告 → "要不要做这个功能？优先级多高？"
```

---

### 🎯 证人 2：增长负责人 — 老刘

**设定：** 公司增长团队负责人，关注获客、激活、留存、变现全链路。

**行为风格：** 数据导向、关注漏斗、每一步都在算转化率。

**审视重点：**
- 获客渠道（用户从哪来？）
- 激活体验（新用户第一次使用的转化率）
- 留存机制（用户为什么回来？）
- 变现路径（怎么从用户身上赚钱？）

**场景脚本：**
```
第 1 步：看获客渠道 → "用户怎么知道这个产品？"
  → SEO？内容营销？口碑？付费投放？

第 2 步：体验注册流程 → 看激活转化率
  → 注册要几步？激活要几步？每步流失多少？

第 3 步：看留存机制 → "用户第二天会回来吗？"
  → 有没有通知？有没有数据沉淀？有没有习惯养成？

第 4 步：看变现路径 → "怎么赚钱？"
  → 付费分层、功能限制、试用期设计

第 5 步：估算增长模型 → "如果投 100 万，能带来多少用户？"
```

---

### 🎯 证人 3：产品总监 — 王总

**设定：** 公司产品线负责人，需要决定"要不要进入这个赛道"。

**行为风格：** 战略化、全局视角、关注市场格局和资源投入。

**审视重点：**
- 市场机会（这个赛道值不值得做？）
- 竞争格局（我们进去了能排第几？）
- 资源需求（做这个需要多少人/多少时间？）
- 战略价值（做了这个对我们的核心业务有什么帮助？）

**场景脚本：**
```
第 1 步：看市场定位 → "这个赛道有多大？增长多快？"
  → 增量市场 vs 存量市场

第 2 步：看竞品格局 → "现有玩家是谁？份额怎么分？"
  → 有没有垄断？有没有差异化机会？

第 3 步：看技术壁垒 → "我们进去需要多久？"
  → 核心功能的开发量、技术难度

第 4 步：看战略价值 → "做了这个对我们的核心业务有什么帮助？"
  → 流量入口？数据补强？生态补全？

第 5 步：做决策 → "做/不做/先观望"
```

## 产品经理视角专属竞品分析框架

### 竞品发现策略

| 搜索维度 | 搜索关键词 | 优先来源 |
|---------|-----------|---------|
| 直接竞品 | `"[核心功能]" alternatives` | Product Hunt、G2 |
| 同类开源 | `"[核心功能]" open source` | GitHub |
| 垂直竞品 | `"[行业]" + "[功能]"` | 行业网站 |
| 国内竞品 | `"[功能]" 国内 工具` | 知乎、少数派 |
| 替代方案 | `"[用户痛点]" solution` | Google |

### 竞品深度对比维度

| 维度 | 分析方法 | 输出 |
|------|---------|------|
| 功能对比 | 逐项列出两边的功能 | 功能对比表 |
| 交互对比 | 还原两边的操作路径 | 效率对比（步数/时间） |
| 技术对比 | 分析两边的技术栈 | 架构差异 |
| 数据对比 | 对比数据能力 | 数据壁垒评估 |
| 定价对比 | 对比收费模式 | 定价策略分析 |
| 口碑对比 | 搜索用户评价 | 用户满意度对比 |
